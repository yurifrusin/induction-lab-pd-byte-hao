# Classroom tracking setup

The website is configured to use the Supabase project at `uuuilhircydoqswkyzvr.supabase.co`. Complete these one-time steps before using classroom mode.

## 1. Apply the database migration

1. Open the Supabase project dashboard.
2. Select **SQL Editor** and create a new query.
3. Copy the complete contents of `supabase/migrations/20260903000000_classroom_tracking.sql` into the query.
4. Select **Run**.

The migration creates class sessions, pseudonymous participant progress, realtime updates, validation constraints and Row Level Security policies. It does not create or store student email addresses.

## 2. Enable anonymous student sessions

In the Supabase dashboard, open **Authentication → Sign In / Providers → Anonymous Sign-Ins**, enable the provider and save the change.

Anonymous authentication gives each browser a temporary technical identifier. Students still see no registration, email or password prompt.

## 3. Allow the teacher sign-in return URL

Open **Authentication → URL Configuration**. For this deployment, add this exact **Redirect URL** and save it:

```text
https://yurifrusin.github.io/induction-lab-pd-byte-hao/?teacher=1
```

Keep the return URLs for other active deployments. The original `induction-lab-pd-byte` path and this `induction-lab-pd-byte-hao` path are different URLs; allowing one does not allow the other.

If **Site URL** still contains `http://localhost:3000`, replace it with the production teacher URL above when this is the project's primary deployment. Site URL is the project-wide fallback, so preserve the intended primary site if this Supabase project is shared with another deployment.

For local testing, also add:

```text
http://127.0.0.1:5173/?teacher=1
```

Email authentication is already enabled in this project. The teacher dashboard uses a passwordless email link.

### If an email link lands on localhost

The app passes its current website path plus `?teacher=1` as `emailRedirectTo`. A redirect to localhost indicates that the authentication configuration or email template needs checking; changing game code alone does not update the hosted Supabase settings.

1. Verify that the exact production teacher URL is saved under **Redirect URLs**.
2. Verify the project's production **Site URL** as described above.
3. If the email templates were customised, check **Confirm signup** and **Magic link**. Their authentication links must preserve the requested return destination. Standard Supabase links use `{{ .ConfirmationURL }}`; a custom link that hard-codes localhost or only uses `{{ .SiteURL }}` can ignore `emailRedirectTo`.
4. Request a new sign-in email from the production teacher page and use that new link. A previously issued link is not rewritten by a configuration change.
5. Verify that sign-in returns to `?teacher=1` and opens the teacher dashboard.

Do not paste access tokens, refresh tokens, or complete sign-in URLs into source files, issues, or screenshots.

Official references: [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls), [Wrong redirect destination troubleshooting](https://supabase.com/docs/guides/troubleshooting/why-am-i-being-redirected-to-the-wrong-url-when-using-auth-redirectto-option-_vqIeO).
